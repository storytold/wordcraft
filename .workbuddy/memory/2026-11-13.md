**关键发现（以后做 PDF 功能先查这里）**
- `hayro-syntax 0.7.2` 自己不暴露 annotations，但 `Page::raw() -> &Dict`、`Dict::entries()`（给 `MaybeRef<Object>`）、`Dict::obj_id()`、`XRef::get::<T>(ObjectIdentifier)` 全公开，可以自己解析 `/Annots`。
- `hayro-interpret` 的 `Device` trait、`interpret_page()`、`Context::new()`、`InterpreterCache::new()` 都公开；`draw_glyph` 给出 `Glyph::as_unicode() -> Option<BfString>` 与 `transform * glyph_transform`，**连 invisible text 也回调**（源码注释明说是给文本提取用）。不需要自己写内容流解释器 / ToUnicode CMap 解析。`InterpreterSettings::default()` 可直接用。
- 字形坐标：`initial_transform(true).to_kurbo()`（注意是 `true`，与 `hayro::render()` 一致），full affine 乘 (0,0) 得基线原点；`sqrt(a²+b²)*1000` 是字号（glyph_transform 含 1/1000 em）。
- 本书 `/Dest` 是命名目标（EPUB 残留的 `file:///...#锚点`），必须在 catalog `/Dests` 里查；dest 数组第一项可以是 **0-based 页码数字**或页对象引用，两种都要支持。
- 只在 pdfview 的 Cargo.toml 声明了 workspace 已有的 `kurbo`（0.13.1 原本就在 Cargo.lock 里）；Cargo.lock 只多了一行 deps 列表条目，**依赖树没有新增 crate**。

- 新增 `crates/pdfview/src/links.rs`：解析 `/Annots` 的 Link、显式/命名/GoTo 目标、`/Dests` 字典与 `/Names` name tree、`/A /URI`；`PdfRect::from_pdf` 用 initial_transform 把 y-up 翻成 y-down；有注释数/名字长度/树深度上限。

## 右键菜单「复制」在 PDF 下无效（bugfix）

用户实测：Ctrl+C 能复制，右键 › 复制没反应。

**根因**：`canvas.rs::context_menu()` 的 Copy 项是 `app.run("edit.copy", …)` → `execute_user` → `execute` → `session.run("edit.copy")` 读的是 PDF 背后的**空白占位 Document**，返回 `{"text":""}`；`run()` 里的 `system_clipboard::put_result` 调 `put()`，而 `put()` 在 text 为空时直接 return，剪贴板什么都没写。Ctrl+C 走的是 `keys.rs::canvas_events` 的 `Event::Copy` 分支（之前加过 PDF 特判），所以能用。**同一个用户动作有两条命令路径，只修了一条。**

**修复**
- `lib.rs::execute()` 在 `ui_command` 之前加 PDF 特判：`id == "edit.copy" && session.pdf_view().is_some()` → `pdf_selected_text()`，有 `self.ctx` 就 `system_clipboard::put`（立即写），否则退回 `canvas.pdf_copy_text` 由 frame tail 写，返回 `{"text": ...}`。这样 ribbon / 右键菜单 / keytips / `engine.execute` / MCP 全部统一。`edit.cut` 仍由 engine 的 `pdf_blocks()` 只读门禁拒绝。
- `canvas.rs::context_menu()` PDF 模式下只显示 Copy 后 return，不再列出 Cut/Paste/Font/Paragraph/Link/New Comment 这些点了必被拒的编辑项。右键不会清掉 `pdf_selection`（`pdf_mouse` 只看 `resp.clicked()`，右键是 `secondary_clicked()`）。
- 新增回归测试 `lib.rs::tests::pdf_edit_copy_reads_the_pdf_text_layer`：内联一段带 /ToUnicode CMap 的极简 PDF（base64，文字 "Hello"），断言 `edit.copy` / `execute("edit.copy")` / `ui.pdf.copy` 三者返回一致文本、剪贴板确实收到 `OutputCommand::CopyText`、`edit.cut` 被拒、`file.new` 后恢复普通 Copy。
- 文档同步：README.md、docs/control-protocol.md、docs/file-format-parity.md 都补上右键/功能区复制走同一文本层。

**两个踩坑**
