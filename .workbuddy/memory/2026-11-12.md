# 2026-11-12

## PDF 打开与只读显示（用户问「能否用 pdfium-render」）

**结论：没用 pdfium-render，改用 hayro 0.7.1；语义是只读页视图，不做 PDF Reflow。**
用户从两个选项里确认了 hayro + 只读查看。

- 不选 pdfium-render 的原因：crate 不含 PDFium 本体，运行时要绑定约 30 MB 的 C++ 动态库
  （每个平台一份），web 版还要外部 pdfium.wasm + JS 胶水；与 AGENTS.md 的
  "Rust only / Never break wasm" 和四平台单二进制分发冲突。PDFium 本身许可（BSD-3-Clause）
  不是障碍，障碍是二进制分发与打包。
- 选 hayro 的原因：`crates/pdf/Cargo.toml` 的 dev-deps 已有 hayro-syntax 0.7.2 /
  hayro-interpret 0.7.0；hayro 0.7.1 依赖完全相同版本、image 0.25、kurbo 0.13，
  用 vello_cpu 光栅化（和 `crates/render` 同源），`forbid(unsafe_code)`，
  MIT OR Apache-2.0，可直接编译到 wasm32-unknown-unknown。输出 Pixmap 是
  premultiplied RGBA8，与 `wordcraft_render::Rendered` 格式一致。
- 代价：不支持加密 PDF、混合/隔离组、knockout groups；页面是位图，文字不可选、不可编辑。

## 落地结构

- 新 L3 crate `crates/pdfview`（`wordcraft-pdfview`）：持有 owned `hayro_syntax::Pdf`
  （无生命周期参数）、每页尺寸、`render(index, scale) -> Raster`。有 MAX_PDF_BYTES /
  MAX_PAGES / MAX_SIDE / MAX_RASTER_PIXELS 上限，解析和渲染都包了 catch_unwind。
  登记在 `xtask/src/layers.rs` TABLE。
- 分层注意：`layers.rs` 禁止 `to >= layer`，所以 L3 不能依赖同层的 `wordcraft-render`；
  合成 `DocLayout` 放在 L4 的 `crates/engine/src/pdf_view.rs`，UI 通过
  `wordcraft_engine::PdfView` 使用，不给 ui-egui 新增依赖。
- engine：`io.rs` 的 `OPEN_EXTS` 加 pdf、`is_pdf` / `open_pdf_bytes` / `read_pdf_path`
  （wasm 侧返回明确错误）、`open_by_content` 加 `%PDF-` 提示；`cmd/file.rs::open`
  在文档导入器之前拦截 PDF（native path 与 wasm base64 data 两条通道都走）；
  `Session.pdf: Option<Arc<PdfView>>`、`layout()` 提前返回合成布局、
  `set_pdf_view`、`set_document` 清 PDF、`run()` 的 `pdf_blocks()` 只读门禁
  （拒绝 mutates 与 file.save/export/print/encrypt）。
- ui-egui：`canvas.rs` 在渲染循环里用 `pdf_view.render(i, scale_px)` 替换
  `wordcraft_render::render_page`；PDF 模式禁用 tiled、跳过 texel_aligned_rect、
  隐藏 caret/IME；`view_key` 加 `document_id` + pdf 开关使切换文档时纹理失效。
  标题加 " (PDF)"（格式名，不走 i18n，避免给 22 个 tsv 加词条）。
  native 与 web 的对话框扩展名白名单都加 pdf。
