Recovery discovery no longer interrupts an explicitly created or opened document. Older copies remain in File › Recover, whose buttons use the interface palette. See [local recovery](recovery.md).

How WordCraft looks and feels next to Word: ribbon, dialogs, panes, keyboard, mouse and touch.
Typing behaviour has its own checklist ([`typing-parity.md`](typing-parity.md)). All assets are our
own (`AGENTS.md`: no Microsoft iconography, ever).

Document title opens Rename Document; the account badge opens Options › General for user name and initials. Saved documents retain their format and refuse conflicting names; desktop renaming requires a filesystem that supports hard links. Web renaming changes the next download name. An unsaved document's name is only the name Save suggests: its Title property is left alone.

## Find and Replace: regular expressions (#4177)

With **Regular expressions** on (Search Options), Replace with expands capture groups: `$1`…`$n`, `${n}`, `${name}` and `$name` (the longest run of letters, digits and `_`), `$0` / `${0}` (the whole match), and `\1`…`\9` as in wildcard Replace; `$$` is a dollar sign, `\t` a tab, `\\` a backslash, `\$` and `\^` a `$` or `^` as typed, and `\n` a paragraph mark, which splits the paragraph as `^p` does (Replace All stays one undo step). Word's `^&`, `^p`, `^t`, `^c` and the other `^` codes work there too (with Special characters off, only the `^` codes are taken literally). A group that doesn't exist, didn't take part in the match or is out of range expands to nothing; a `$` that starts no group, an unclosed `${`, and other `\` escapes stay as written. Plain and wildcard Replace are unchanged. Word has no regular-expression mode; this follows the Rust `regex` crate's Replace syntax.

## Find and Replace: the text boxes' right-click menu (#4404)

A right-click in **Find what**, **Replace with** or Go To's **Enter page number** opens **Cut**, **Copy**, **Paste** and **Select All**, as the system's text boxes in Word's dialogs have; before, a right-click there did nothing and only Ctrl+V pasted. As on the page, a right-click in the box's selection keeps it, so Cut and Copy (greyed out without one) take what was selected, and a right-click elsewhere moves the caret there, so Paste goes where you clicked. Paste reads the system clipboard's text into the box, never into the document, and behaves as Ctrl+V does there: it replaces the selection, and line breaks become spaces in the one-line box. The dialog stays open and the box keeps the keyboard. On the web, where a page can only read the clipboard on Ctrl+V, Paste is greyed out. Word's Windows menu also has Undo, Delete and the right-to-left entries; Ctrl+Z still undoes in the box. The menu is `crate::field_menu::text_field`, ready for the other dialogs' text boxes.

Footnote and endnote editing keeps body and note text at normal opacity, on light and dark pages. Headers and footers still dim outside their editing context (#2545).
